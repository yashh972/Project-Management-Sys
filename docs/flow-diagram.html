Agile CodeBoard: how it fits together

Five pictures of the running system: where data lives, how a task moves, who sees what, how the ML job turns history into scores, and what happens when you press "Suggest assignee".

1 System2 Task lifecycle3 Access4 ML job5 Smart assignment

1. System: one database, two programs that read it

The PHP app serves every page. A separate Python program reads the same SQLite file in batches and writes scores back into it. The pages never run the models themselves, except the assignment suggestion, which starts Python on demand.

2. A task from creation to done

Every status change writes a history row with the time and the person. The ML job reads those rows to learn when work started and whether it was reopened.

3. Who sees what

One analytics address serves everyone. The controller decides the scope once, at the start, and every query after that follows it.

4. The ML job: history in, scores out

It learns what is normal for a task without looking at who did it, then compares each person with that. That is why someone handed hard work isn't ranked below someone handed easy work.

5. What happens when you press "Suggest assignee"

The only moment a page triggers Python. It takes about three seconds, which is why the button shows a progress message.
